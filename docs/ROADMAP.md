# Roadmap

From the current prototype to the full 5-level game, playable in color on GBC and in
4 shades on DMG.

Workflow: Claude writes the code. The owner runs git (branches, commits, PRs), reviews,
and plays it in Emulicious and on hardware. Each milestone ends with PyBoy tests passing
in both modes.

Items marked **(owner)** need the owner: hardware, installs, or creative decisions.

The physics and level loading (M2) come before color (M4) and art (M5) on purpose. Level
layouts depend on the jump, so the jump has to be final before level design starts.
Levels are designed with plain blocks first, so design doesn't wait for art.

---

## M0 — Toolchain and test loop

Done when `make && make test` builds the ROM and runs a smoke test in DMG and GBC mode.

- [x] **(owner)** Install GBDK-2020 4.5.0 into `gbdk/` (`gbdk-win64.zip` from GitHub releases).
- [x] **(owner)** Emulicious into `emulicious/` for manual debugging.
- [ ] Rewrite the Makefile: one rule that finds all `src/**/*.c`, plus the header and
      cartridge flags from [CGB_PLAN.md](CGB_PLAN.md) section 1 and `-Wm-yS` for symbols.
      **Urgent:** ROM bank 0 has 85 bytes free. MBC5 + `-autobank` and banked assets
      free it up. The Makefile must also work from Git Bash, not only PowerShell/cmd.
      Flags and banking rules: [RESEARCH.md](RESEARCH.md) section 2.1.
- [ ] Fix `make assets`: png2asset ignores `-bank`, `-org` and `-name`. Use `-b 255`
      and load banked assets through `NONBANKED` loaders.
- [ ] ROM layout check after linking: `romusage -R`, `_HOME` below `0x4000`, header
      bytes `0x143 = 0x80` and `0x147 = 0x1B`.
- [ ] `tools/requirements.txt`, `.venv` setup, and gitignore entries.
- [ ] PyBoy harness: `tests/conftest.py`, `tests/gamelib.py`, and a boot smoke test.
- [ ] Save-persistence test ROM: write a counter to cartridge RAM, read it after a power
      cycle. **(owner)** Run it on the EverDrive clone. If saves don't persist, switch
      to a password system.
- [ ] GitHub Actions CI: build and test on every PR.
- [ ] Remove dead code and files listed in [PROJECT_STATE.md](PROJECT_STATE.md).

## M2 — Physics and level loading

Done when a greybox level made in Tiled loads, scrolls past 256 px, and plays with the
new physics, and the jump metrics are written into [LEVEL_DESIGN.md](LEVEL_DESIGN.md).

- [ ] **(owner)** Confirm Tiled as the level editor ([LEVEL_PIPELINE.md](LEVEL_PIPELINE.md)).
- [ ] Sub-pixel physics: positions in 1/32 px (`uint16_t`), two gravities (jump cut on
      release), apex hang, coyote time, jump buffering, head-corner correction. Starting
      values in [RESEARCH.md](RESEARCH.md) section 2.2.
- [ ] Camera: deadzone, 24 px look-ahead, and a lock behind opened gates.
- [ ] Collision: player box against tiles on both axes at all edges, plus one-way
      platforms and hazards.
- [ ] Measure the jump and fill in [LEVEL_DESIGN.md](LEVEL_DESIGN.md) section 4.
- [ ] Greybox tileset: plain blocks for solid, one-way, hazard, gate, exit and fragment
      markers. Generated by a script, readable on DMG.
- [ ] `tools/tiled2c.py` and `make levels`.
- [ ] Collision ring in WRAM (32×16, 512 bytes), filled from the tileset table as columns
      stream in. Delete the old collision map.
- [ ] Map streaming with `set_bkg_submap` for levels wider than 256 px.
- [ ] `tools/levelpreview.py`: full-level PNG with column numbers and jump arcs, plus the
      reachability check.

## Order and dependencies

```
M0 ─► M1 ─► M2 ─► M3 ─► M5 ─► M8 ─► M9
         │               ▲
         └─► M4 ─────────┘      (color before the art pass)

             M3 ─► M6 ─► M8      (audio in parallel)
             M3 ─► M7 ─► M9      (saves and flow in parallel)
```

The save test in M0 runs early on purpose, so the cartridge type is settled before save
code is written.
