This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**ApexLab: Code Breach** is a Game Boy platformer built with [GBDK](https://github.com/gbdk-2015/gbdk-2015) (Game Boy Development Kit). The toolchain (GBDK + Emulicious emulator) is bundled in the repo under `gbdk/` and `emulicious/`. Target: original Game Boy hardware constraints (SM83 CPU, 8KB VRAM, 8KB WRAM).

## Build Commands

```bash
# Full build (clean + compile)
make

# Run in Emulicious emulator (requires Java)
make run

# Regenerate asset .c files from PNG sources
make assets

# Clean build artifacts
make clean
```

The compiled ROM is output to `obj/ApexLab.gb`. `make all` runs `clean` then `prepare` then links — always a fresh build.

**Asset pipeline**: PNG files in `graphics/` are converted to GBDK-compatible C source files via `png2asset`. Run `make assets` after modifying any PNG, then commit both the PNG and the regenerated `.c`/`.h` in `src/graphics/`.

## Architecture

### Game State Machine (`src/main.c`)

The main loop is a state machine with these states (defined in `src/utils.h`):
- `INTRO_CREDITS_STATE` → `TITLE_SCREEN_STATE` → `GAMEPLAY_START` → `COREGAMELOOP` → `GAMEPLAY_END`

Global state lives in `main.c`: `joypad_current`, `joypad_previous`, `scroll_value`, `total_scroll_x`, `current_game_state`, plus singleton instances `Player player` and `LevelManager level_manager`.

### Module Breakdown

| Directory | Purpose |
|---|---|
| `src/game_state/` | One file per game state: `prepare_gameboy`, `intro_credits`, `start_screen`, `core_game_loop`, `game_over` |
| `src/player/` | `Player` struct + physics: `player_handle_movement_physics`, `player_handle_jumping_physics`, `player_draw`, collision detection |
| `src/input/` | Joypad polling and translating button state into player forces/scroll deltas |
| `src/level/` | `LevelManager` + `Level` structs, tile-based collision map (20×18 tiles), level loading (`level_1_server_room_init`), HUD and sprite setup |
| `src/graphics/` | Generated asset files (programmer sprite, logo, backgrounds, HUD, mushroom enemy) — most are auto-generated by `make assets` |
| `res/` | Raw resource files |
| `graphics/` | Source PNG files for the asset pipeline |

### Player Physics (`src/player/player.h`, `src/player/player.c`)

Physics uses integer arithmetic (no floats — Game Boy has no FPU):
- Horizontal: `velocity_x`, `movement_force_x`, `slowing_x` for deceleration over `DECELERATION_FRAMES`
- Vertical: `velocity_y` clamped to `[MIN_VELOCITY_Y, MAX_VELOCITY_Y]`, `jump_frames` counter up to `MAX_JUMP_FRAMES`
- Ground detection via `underfoot_state` (`FOOT_ON_LAND` / `FOOT_IN_AIR`)
- `scroll_x` (accumulated from background scrolling) is passed into collision functions to translate world-space tile coordinates

### Level Collision (`src/level/level_manager.h`)

`Level.collision_map[LEVEL_HEIGHT][LEVEL_WIDTH]` is an 18×20 byte array. Tile types: `COLLISION_NONE`, `COLLISION_SOLID`, `COLLISION_ONE_WAY`, `COLLISION_HAZARD`, `COLLISION_COLLECTIBLE`. `level_check_collision()` converts pixel coords + scroll offset to tile indices.

### Scrolling

Background scrolls horizontally; `scroll_value` is set by input handling and applied each frame via `scroll_bkg()`. `total_scroll_x` accumulates the running world offset for collision coordinate translation.

## Development Feature Flags (`src/utils.h`)

Toggle these `#define` values to change behavior without restructuring code:

| Flag | Default | Effect |
|---|---|---|
| `SKIP_INTRO_AND_START` | `1` | Skip intro/title screens, jump straight to gameplay |
| `EMPTY_BACKGROUND` | `0` | Render blank background (collision debugging) |
| `DISABLE_BACKGROUND_SCROLLING` | `0` | Freeze background scroll |

## Game Boy Constraints to Keep in Mind

- **No floats**: all physics math uses `int8_t`/`int16_t`/`uint8_t`.
- **VRAM timing**: tile/map writes must happen during VBlank or HBlank. Use `wait_vbl_done()` at end of main loop (already in place).
- **Sprite limit**: 10 sprites per scanline, 40 total OAM slots. The player uses 8×16 metasprites (`SPRITES_8x16` mode).
- **ROM banking**: assets in bank 1 use `-bank 1 -org 0x8000` flags in `make assets`. Access banked data with `SWITCH_ROM_BANK`.
- **Stack is tiny**: avoid deep recursion and large stack allocations.
